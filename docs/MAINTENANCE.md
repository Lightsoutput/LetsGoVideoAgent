# LetsGoVideoAgent 维护文档

## 1. 文档目的

本文既是项目维护手册，也是 V1.0 的实施基线，用于记录项目结构、已落地能力、目标能力、验收标准、运行维护方式和主要风险。每次较大的架构、模型、数据结构、Prompt、Skill 或部署方式变更后，应同步更新本文。

## 2. V1.0 定位与原则

LetsGoVideoAgent V1.0 是一个**通用视频理解 Agent 系统**。它不只执行语音转写、OCR 和抽帧，而是将声音、字幕、画面、人物、事件顺序和上下文组织成可追溯的视频语义模型，让用户能够快速理解整段视频，也能针对章节、片段和精确时间点进行问答。

V1.0 同时为后续垂类化预留 Skill 机制：通用能力保持稳定，游戏攻略、访谈、课程、Vlog 等领域知识通过 Skill 增强，不向基础 Prompt 中不断添加某个视频的特殊规则。

核心原则：

- **理解优先**：摘要必须解释“谁在什么场景下做了什么、为什么、结果如何”，不能只是拼接 OCR、字幕原句或界面文字。
- **多模态互证**：ASR、原站字幕、OCR、VLM、时间连续性和搜索结果相互校验，并保留每项结论的来源。
- **证据可追溯**：章节、摘要和回答都应尽量关联时间范围、代表帧、字幕或模型分析记录。
- **通用内核、Skill 扩展**：基础流程不依赖垂类关键词；领域术语、分析维度和工作流由可版本化 Skill 注入。
- **成本可控制**：模型路由、缓存、预算和降级策略由 Harness 统一管理，前端可查看实际费用。
- **过程可观察**：用户能看到 Agent 正在做什么、调用了什么工具、为何重试或降级，而不是只看到一个等待进度。

## 4. 已落地能力

- 支持本地上传和网页视频导入，B 站下载由 yt-dlp 负责。
- 使用 Faster-Whisper 转写语音，并优先读取可下载的原站 VTT/SRT 字幕。
- 使用 OCR、说话人分析和 Qwen3-VL 画面理解构建多轨时间轴。
- 使用 DeepSeek 生成视频概述、语义章节、快捷问答和字幕审校结果。
- 当前帧问答按精确时间戳抽帧，再交给 VLM；网络失败时仅对同一帧做 OCR 降级。
- QA 使用 LangGraph 的“调查—验证—补充检索”流程。
- 自研 Agent Harness 控制步骤、工具权限、超时、重复调用、Token 和费用。
- SearXNG 搜索已封装为 MCP，提供搜索、术语核验和健康检查工具。
- 前端提供视频预览、字幕、章节、代表帧、多轨时间轴和证据回放。
- 模型调用成本以人民币记录到 `data/costs/model-usage.jsonl`。

## 5. V1.0 目标工作流

```text
视频输入
  → 下载/上传与媒体探测
  → 音频、字幕、镜头和候选帧提取
  → ASR/说话人/OCR/VLM 并行分析
  → 多模态时间对齐与术语审校
  → 事件、主题、因果关系和视频意图建模
  → 大节/小节聚类与代表帧选择
  → 视频总览、章节摘要和预设问答生成
  → 用户按全局/片段/当前帧进行问答
  → 用户反馈进入评测、记忆或 Skill 迭代流程
```

处理过程必须保存结构化中间结果，不能只保留最终自然语言。建议形成以下语义层：

1. **感知层**：字幕词句、说话人片段、OCR 区域、镜头变化、物体和界面元素。
2. **对齐层**：统一时间戳，记录同一时刻的语音、画面、人物和来源置信度。
3. **事件层**：识别动作、讨论主题、状态变化、问题与回答、操作与结果。
4. **叙事层**：理解视频类型、创作者目的、章节逻辑、前后因果及核心结论。
5. **交互层**：根据问题选择相关证据，必要时对精确帧重新调用 VLM，再由 LLM 组织回答。

### 5.1 “真正理解视频”的最低验收标准

- 总结能够说明视频主题、目标、主要参与者、关键过程、重要结论和必要背景。
- 章节标题是语义概括，不得直接使用口水话、残缺字幕或孤立 OCR 文本。
- 片段摘要能独立读懂，明确主语和上下文，不出现“然后就是一些……”等不完整表达。
- 对当前帧的回答必须使用该帧对应的真实图片；回答涉及前后过程时，要明确区分“当前画面可见”和“结合上下文推断”。
- 专业名词优先参考原视频字幕和画面文字，经上下文、搜索及 LLM 联合校验后再改写。
- 所有重要结论可定位到时间范围和证据，模型不确定时应明确表达，而非编造。
- 在游戏、访谈、课程和生活/Vlog 四类评测集中，均需通过人工事实一致性和可理解性评分，禁止只针对单个样例调 Prompt。

## 6. V1.0 功能需求

### 6.1 成本中心

前端新增成本面板，显示：

- DeepSeek、Qwen-VL、ASR、搜索及其他 API 的请求次数、Token/图像数量、原币费用和折算人民币费用。
- 单视频、单任务、单 Agent、单模型以及时间范围内的成本。
- 缓存命中节省、重试浪费、降级次数和预算剩余。
- 模型定价版本、汇率来源和估算/账单实付的区别。

后端所有外部调用统一产生 `UsageEvent`，至少包含 `trace_id`、`task_id`、`agent_id`、`provider`、`model`、输入/输出用量、单价、人民币成本、缓存状态和时间。费用不可散落在各模型适配器中自行计算，应由统一计费服务汇总。

### 6.2 Agent 协同可视化

新增“Agent 工作台”，以时间线或有向图展示：

- 当前参与的 Agent、状态、输入、输出摘要、耗时和费用。
- Agent 之间的任务委派、依赖关系、并行执行和汇合节点。
- 每次模型、MCP、工具、Skill、记忆和缓存调用。
- 重试、超时、人工确认、降级和失败原因。
- 点击节点可查看经过脱敏的 Prompt 摘要、结构化结果和证据，不默认暴露 API Key、完整系统提示或敏感视频内容。

该界面基于统一 Trace 事件构建，不允许前端凭日志文本猜测 Agent 状态。

### 6.3 Agent Harness 可视化与控制

Harness 是 Agent 的运行控制层，不是一个负责内容理解的独立 Agent。V1.0 需要展示并允许配置：

- 最大步骤、超时、并发数、重试次数、Token/费用预算。
- Agent 和工具权限、允许调用的 MCP、模型路由及降级顺序。
- 循环调用检测、重复工具调用抑制、异常中断和断点恢复。
- 人工介入点，例如批准高成本视觉分析、接受字幕纠正或发布新 Skill。

所有配置应有安全默认值；高级设置可折叠，避免普通用户必须理解 Agent 内部参数才能使用。

### 6.4 MCP 中心

将 SearXNG 搜索继续作为 MCP 工具，并新增 MCP 管理视图，展示服务健康、工具列表、调用次数、耗时、失败率及最近错误。后续视频下载、知识库或第三方数据源可按实际收益封装为 MCP，但普通内部函数无需为了展示效果强行 MCP 化。

搜索主要用于术语与事实校验，搜索结果必须记录来源链接、查询词和时间；不能因为搜索到同名词就直接覆盖原字幕。

### 6.5 Skill Studio：从通用系统走向垂类系统

新增独立的 Skill Studio，支持两种创建入口：

1. **单视频对话创建**：用户选择一个已分析视频，Agent 归纳该类视频所需术语、分析维度、分段方式和输出格式，并通过对话询问用户目标。
2. **多视频归纳创建**：用户选择多个本地视频或视频链接，系统比较共性与差异，生成更稳定的领域 Skill 草案。

建议流程：

```text
选择样本与目标
  → 分析样本共性和失败案例
  → Agent 生成 Skill 草案
  → 用户对话补充/修改需求
  → 静态安全检查
  → 在保留评测集上对比通用基线
  → 用户确认后发布版本
  → 运行监控与回滚
```

Skill 至少包含：

- 名称、适用视频类型、版本、作者、输入/输出契约。
- 领域术语及检索策略，而不是简单关键词替换表。
- 推荐的分段线索、视觉关注点、问答策略和输出模板。
- 可调用的 Agent、MCP 和工具白名单，以及模型/费用建议。
- 正例、反例、边界条件和自动评测用例。
- 生成依据、适用范围、已知限制和回滚版本。

自动生成的 Skill 必须先作为草案，不能直接获得 Shell、文件写入或外部发布权限。通用 Prompt 与 Skill 分离，运行时记录使用了哪个 Skill 及其版本，支持禁用、对比和回滚。

### 6.6 快速理解与问答

视频处理完成后，用户无需主动提问即可看到：视频一句话定位、完整摘要、大节/小节、关键结论、代表帧和预设问题。问答入口支持全视频、选中章节、选中时间范围和当前帧四种范围，并明确显示所用模型、Skill、证据和是否发生降级。

## 7. V1.0 Agent 划分建议

多 Agent 应按职责和可独立评测的边界划分，避免为了数量而拆分：

| Agent | 主要职责 | 关键输出 |
| --- | --- | --- |
| Ingestion Agent | 下载、媒体探测、字幕来源判断 | 可处理媒体与元数据 |
| Perception Agent | 协调 ASR、OCR、VLM、说话人分析 | 时间对齐的感知事实 |
| Understanding Agent | 事件、主题、视频意图和叙事逻辑建模 | 语义事件图/上下文 |
| Segmentation Agent | 基于画面、语音和叙事边界生成层级章节 | 大节、小节和边界依据 |
| Verification Agent | 字幕术语、事实与证据一致性核验 | 修订建议及置信度 |
| QA Agent | 计划检索、当前帧分析、证据组织和回答 | 带时间戳的答案 |
| Skill Builder Agent | 从样本和用户反馈生成/修改 Skill 草案 | 可评测的 Skill 版本 |

Harness 统一编排这些 Agent，并负责权限、预算、Trace、重试和人工介入。确定性媒体工具仍保持普通服务或工具，不必包装成会自由决策的 Agent。

## 8. 数据与可观测性设计

V1.0 应优先完成 MySQL 持久化，并至少规划以下实体：`videos`、`processing_jobs`、`artifacts`、`chapters`、`evidence`、`agent_runs`、`trace_events`、`usage_events`、`skills`、`skill_versions`、`eval_runs` 和 `user_feedback`。大文件和截图存对象存储或本地 `data/`，MySQL 只保存元数据和引用。

每次视频处理和问答生成全局 `trace_id`，贯通前端请求、Agent、模型、MCP、成本和日志。Trace 至少采用以下事件类型：

- `agent.started/completed/failed`
- `model.requested/completed`
- `tool.called/returned`
- `mcp.called/returned`
- `skill.loaded/validated`
- `budget.updated`
- `human.approved/rejected`

优先采用 OpenTelemetry 兼容字段，前端自建适合求职演示的 Agent 工作台；后续可接 Langfuse 或其他 Trace 平台，但不能让核心数据只存在第三方平台。

## 9. 版本实施顺序

### P0：正确理解与可靠存储

- MySQL、任务状态持久化、断点恢复和幂等重试。
- 统一多模态语义模型，修复字幕/画面/时间戳错位。
- 重构章节与摘要，使其基于事件和叙事逻辑，而非 OCR/ASR 拼接。
- 建立四类视频的基准评测集和人工评分规范。

### P1：可观察、可计费、可控制

- 统一 Trace/Usage 事件。
- 成本中心、Agent 工作台、Harness 和 MCP 状态页。
- 单视频处理详情中展示模型、证据、重试和降级过程。

### P2：Skill Studio

- 单视频/多视频 Skill 草案生成。
- 用户对话修改、权限检查、版本管理和回滚。
- 通用基线与 Skill 增强效果、质量和成本对比。

### P3：产品化完善

- 权限与隐私治理、对象存储、队列扩展和部署文档。
- 评测门禁、成本告警、监控看板和异常恢复演练。

## 10. V1.0 完成定义

以下条件同时满足，才可将版本标记为 V1.0：

- 四类通用视频评测均达到约定的章节、摘要、当前帧和问答质量门槛。
- 用户可以快速浏览总览和章节，无需通过提问才能理解视频。
- 每个关键结论都有可访问的时间戳或视觉/文本证据。
- Agent、模型、MCP、Skill、Harness 状态及费用在前端可追踪。
- 任务可在服务重启后恢复，失败有自动重试且不会重复计费或生成重复数据。
- Skill 可由单/多视频生成草案，经用户修改、评测、发布和回滚。
- API Key 不进入日志/Trace，视频和模型数据的保留策略清晰。
- 后端、前端、集成测试和评测流程均有可重复执行的命令与文档。

## 12. 维护约定

### 日志

- 所有服务日志写入 `var/logs/<service>/`，不得写在项目根目录。
- 日志文件建议命名为 `<service>.<date>.out.log` 和 `<service>.<date>.err.log`。
- 默认保留 14 天。先预览再清理：

```powershell
.\scripts\cleanup-logs.ps1 -RetentionDays 14 -WhatIf
.\scripts\cleanup-logs.ps1 -RetentionDays 14
```

可使用 Windows 任务计划程序每天执行一次清理脚本。日志清理只针对 `var/logs`，不会删除视频、缓存或模型。

### 外部 API 网络

- 本机直连 HTTPS 被限制时，通过 `.env` 的 `OUTBOUND_HTTP_PROXY` 配置统一出站代理。
- 当前本机 Clash HTTP 代理为 `http://127.0.0.1:7890`；更换代理软件或端口后必须同步修改。
- SiliconFlow 与 DeepSeek 共用该配置；SearXNG 等本地地址不经过代理。
- 排查顺序：代理端口监听 → `/v1/models` 连通 → 单帧 VLM smoke test → DeepSeek JSON smoke test → 浏览器问答。

### 代码和文件

- API、领域模型、基础设施适配器和 Agent 角色保持分层，不从 Agent 直接访问 Shell 或数据库。
- 新运行时文件应进入 `data/`、`var/` 或 `artifacts/`，不能堆放在根目录。
- 新密钥只写 `.env`，不得写进源码、日志、文档或 Git。
- 修改 Prompt、缓存格式或模型输出结构时，递增 Prompt/缓存版本并补充测试。
- 提交前至少执行 Ruff、MyPy、Pytest、前端 TypeScript 和 ESLint 检查。

## 13. 主要风险

- **数据丢失**：当前默认使用内存仓库，重启后记录消失；应优先完成 MySQL 持久化。
- **外部 API 不稳定**：硅基流动、DeepSeek 或搜索网络异常会影响增强能力；必须保留超时、重试、降级和明确提示。
- **证据错位**：抽帧时间、VLM 输入、截图 URL 和回答证据必须使用同一时间戳，禁止用邻近旧证据冒充当前帧。
- **识别误差传播**：字幕、OCR 或视觉理解错误会继续影响章节与问答；需要来源优先级、术语核验和评测集。
- **成本失控**：逐帧 VLM 和多次 LLM 审校成本较高；应通过代表帧、缓存、Harness 预算和成本告警控制。
- **版权与隐私**：网页下载必须确认使用权；上传视频、字幕、截图和日志可能包含敏感内容。
- **伪理解**：模型可能用流畅语言包装错误的 OCR/ASR；摘要必须经过多模态证据约束和评测，不能以语言自然度代替正确性。
- **Skill 过拟合**：少量样本生成的 Skill 可能只适用于某个 UP 主或固定模板；发布前必须使用未参与生成的保留视频评测。
- **权限扩大**：自动生成的 Skill 若可自由调用工具会形成安全风险；必须使用白名单、静态检查、人工发布和版本回滚。
- **可视化泄密**：Trace 可能包含 Prompt、字幕、图片及搜索词；展示和落盘前需要脱敏及访问控制。
- **多 Agent 复杂度**：Agent 数量增加会抬高延迟和成本；只有具备独立职责、状态和评测标准的节点才应成为 Agent。

## 14. 建议的更新流程

```text
提出问题 → 建立可复现样例 → 定位所属层 → 通用修复 → 添加测试
→ 更新缓存/Prompt版本 → 跑完整检查 → 更新本维护文档
```

避免针对单个视频不断增加关键词或 Prompt 特例。确有垂类需求时，应新增 Skill，并保证通用流程仍可独立工作。
